## Optional Discussions proposal

Discussions is currently disabled. Do not enable it without separate founder approval
and an assigned moderator. Proposed categories:

| Category | Purpose / format |
| --- | --- |
| General | Project questions and non-sensitive developer conversation; open discussion |
| Ideas | Early suggestions; accepted actionable work moves to an Issue |
| Q&A | Installation/report interpretation questions; question/answer format |
| Show and Tell | Voluntary sanitized examples of use and useful findings; open discussion |

Keep reproducible bugs, provider requests and scoped features in Issues. Require
invented minimal examples, never credentials/private source/raw reports/personal
paths. Vulnerabilities go through SECURITY.md, not Discussions. Define moderation
ownership, response expectations and accidental-disclosure handling before enabling;
no SLA or feedback retention policy is invented here. No automatic telemetry or
participant enrollment is introduced.

Human first-run feedback and human acceptance of catalog claims remain valuable;
passing synthetic demos do not replace either. A future release asset or npm package
requires separate authorization and fresh integrity/security review.
